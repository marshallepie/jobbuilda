# R11 event-delivery dependency assessment

**Assessment type:** repository source trace only.
**Scope:** R04–R10 in `RECOVERY_CHECKLIST.md`; this record does not claim non-production execution, event delivery, outbox observation, email capture, provider completion, or release readiness.

## Method and boundary

The trace follows the currently checked-out source to the point at which each workflow records its synchronous result and notes explicit event publication. Several service event-bus implementations catch publish failures and continue (for example, clients at `services/clients-mcp/src/lib/event-bus.ts:23-47`, jobs at `services/jobs-mcp/src/lib/event-bus.ts:23-48`, and quoting at `services/quoting-mcp/src/lib/event-bus.ts:23-47`). No runtime was started and no provider, database, NATS, or other external system was accessed for this assessment.

A repository source search found publishers but no source subscriber/consumer for the `job.created`, `quote.sent`, or `payment.succeeded` subjects identified below. That is an absence-of-source finding, not proof about a deployed topology or runtime configuration.

The map traces selected critical paths for each checklist item, not every route, UI action, tool, event subject, or workflow named by R04–R10. The per-item coverage boundary identifies the paths traced here; all other routes and workflows within that checklist item remain untraced and require their own source and required non-production evidence before release.
